==========================================================================
 1. VISIÓN GENERAL Y CAPAS
==========================================================================

 Estructura de src/main/java/com/softcorp/SoftCorpBackend/:

   SoftCorpBackendApplication.java -> punto de entrada
   auditoria/   -> AuditoriaContext, AuditoriaInterceptor, AuditoriaService
   config/      -> OpenApiConfig (/docs), WebConfig (interceptor)
   controller/  -> endpoints REST (Auth, Perfil, Rol, Modulo, Incidencia,
                   Tecnico, SolicitudRepuesto, InformeTecnico,
                   DiccionarioFalla, Dashboard, Reporte, Historial, AppInfo)
   dto/         -> Request y Response JSON con validaciones (@Valid)
   exception/   -> GlobalExceptionHandler (400, 401, 404, 500 en JSON)
   model/       -> tablas como clases JPA (+ model/auditoria/)
   repository/  -> interfaces JpaRepository (+ repository/auditoria/)
   security/    -> JwtAuthenticationFilter y SecurityConfig
   service/     -> reglas de negocio de Sprints 1 a 4 y JwtUtil
   util/        -> ErrorResponse

 Recorrido de una petición:

   Petición HTTP
     -> JwtAuthenticationFilter (verifica Bearer token y carga usuario/rol)
     -> SecurityConfig          (permisos de ruta -> 401 o 403 si falla)
     -> AuditoriaInterceptor    (preHandle inicializa IP, endpoint, UUID)
     -> Controller              (@Valid sobre DTOs)
     -> Service                 (reglas de negocio + AuditoriaService)
     -> Repository              (consultas JPA o nativas PostgreSQL)
     <- Controller              (200 OK + JSON)

 2. resources/
==========================================================================

 application.properties:
   - server.port=${PORT:8080}
   - spring.config.import=optional:file:.env[.properties]
   - PostgreSQL en Neon (${SPRING_DATASOURCE_URL}, USERNAME, PASSWORD)
   - spring.sql.init.mode=always (ejecuta schema.sql y data.sql al iniciar)
   - spring.jpa.hibernate.ddl-auto=none
   - spring.jpa.open-in-view=false
   - jwt.secret=${TOKEN_JWT_SECRET:...}, jwt.expiration=3600000 (1 hora)
   - app.cors.allowed-origin=${CORS_ALLOWED_ORIGIN:http://localhost:4200}
   - springdoc.swagger-ui.path=/docs (controlable con SPRINGDOC_ENABLED)
   - Actuator expuesto en /actuator: health, info, metrics, beans

 schema.sql (idempotente):
   - Acceso: rol, modulo (con orden_opcion), rol_modulo, persona, usuario
   - Incidencias (Sprint 2 + 3): incidencia (con ubicacion_equipo,
     fecha_traslado, fecha_solucion)
   - Sprint 3: solicitud_repuesto, informe_tecnico, diccionario_falla
   - Auditoría: esquema auditoria con auditoria.evento y auditoria.cambio

 data.sql (idempotente):
   - 3 roles (JEFE, TECNICO, SISTEMAS) y 8 módulos ordenados
   - 5 usuarios de prueba (@sc.pe):
       jefe@sc.pe     / jefe123
       tecnico@sc.pe  / tecnico123  (límite 5)
       atorres@sc.pe  / tecnico123  (límite 3)
       crojas@sc.pe   / tecnico123  (límite 2, empieza sin cupo: 2/2)
       sistemas@sc.pe / sistemas123
   - Incidencias de ejemplo (incluyendo PC-CONT-005 con 3 incidencias
     históricas para HU12), solicitudes de repuesto, informes técnicos y
     entradas en diccionario_falla.


==========================================================================
 3. RESUMEN DE FUNCIONALIDADES POR SPRINT
==========================================================================

 Sprint 1 y 2:
   - AuthService + JwtUtil: registro, login (BCrypt) y perfil con módulos.
   - RolService / ModuloService: gestión de roles (solo JEFE modifica) y
     listado de módulos activos.
   - IncidenciaService:
       HU04 registrar(): normaliza codigoEquipo, estado PENDIENTE, ubicación
       OFICINA_USUARIO, registra evento de auditoría.
       HU05 asignar(): solo JEFE; valida estado PENDIENTE, sin técnico
       previo, rol TECNICO y carga < limiteAtencion.

 Sprint 3:
   - IncidenciaService.misTareas() y obtenerPorId() (HU06): bandeja del
     técnico autenticado con filtro opcional PENDIENTE/SOLUCIONADO.
   - SolicitudRepuestoService (HU07): solicita repuesto para incidencia
     pendiente asignada al técnico; si trasladarEquipo=true, mueve la
     incidencia a AREA_SOPORTE y guarda fecha_traslado. Permite pasar de
     SOLICITADO a RECIBIDO o RECHAZADO.
   - InformeTecnicoService (HU08): impide cerrar la incidencia si existe
     una solicitud de repuesto en estado SOLICITADO; al registrar el
     informe, cambia la incidencia a SOLUCIONADO y registra fecha_solucion.
   - DiccionarioFallaService (HU09): CRUD y búsqueda por keyword/categoría.
   - DashboardService: KPIs de resumen y 5 series/agregaciones para los
     gráficos (evolución diaria, por área, rendimiento técnicos, fallas por
     categoría y repuestos por estado).

 Sprint 4 (PC4):
   - ReporteService.equiposComplicados() (HU10 - solo JEFE):
       Lista incidencias PENDIENTE trasladadas a AREA_SOPORTE o con
       solicitud de repuesto SOLICITADO. Calcula diasTranscurridos y filtra
       por situación (TRASLADADO | ESPERA_REPUESTO | TODOS) y por técnico.
   - ReporteService.solucionadasPorDia() (HU11 - solo JEFE):
       Agrupa equipos SOLUCIONADO por día y técnico en un rango de fechas
       (por defecto últimos 7 días; valida desde <= hasta).
   - HistorialService.historial() (HU12 - cualquier miembro autenticado):
       Consulta por codigoEquipo las incidencias ordenadas de más reciente
       a más antigua, cruza cada una con su InformeTecnico, lista repuestos
       cambiados (estado RECIBIDO) y calcula totalFallas, pendientes,
       solucionadas y reemplazoSugerido (>= 3 fallas).


==========================================================================
 4. SEGURIDAD, AUDITORÍA Y ERRORES
==========================================================================

 SecurityConfig:
   - Rutas públicas: /, /actuator/**, /api/auth/**, /docs/**,
     /swagger-ui/**, /v3/api-docs/**, /error.
   - Solo JEFE: /api/v1/rol/save, /api/v1/rol/delete,
     PUT /api/v1/incidencias/*/asignar, /api/v1/tecnicos/**,
     /api/v1/reportes/**.
   - Solo TECNICO: GET /api/v1/incidencias/mis-tareas,
     POST /api/v1/repuestos, GET /api/v1/repuestos/mis-solicitudes,
     POST /api/v1/informes-tecnicos, POST/PUT /api/v1/diccionario-fallas/**.
   - JEFE o TECNICO: PUT /api/v1/repuestos/*/estado,
     DELETE /api/v1/diccionario-fallas/**.
   - Resto (incluyendo /api/v1/equipos/{codigo}/historial, dashboard,
     incidencias, perfil): cualquier usuario autenticado.

 GlobalExceptionHandler:
   - AuthenticationException / ExpiredJwtException / JwtException -> 401
   - IllegalArgumentException / MethodArgumentNotValidException /
     HttpMessageNotReadableException / MethodArgumentTypeMismatchException /
     DataIntegrityViolationException -> 400
   - NoSuchElementException -> 404
   - Exception -> 500

 Swagger UI: http://localhost:8080/docs
